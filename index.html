Frequently asked questions

The questions gym owners actually ask before signing up.

Do I need to know how to code?

No. Registering your gym, entering your business info, and running the AI receptionist all happen through plain forms in the dashboard — see Getting Started.

Does it work in Taglish?

Yes — try the live demo above. GymBot QC's built-in question list covers common gym questions in English, Tagalog, and Taglish, including shortcuts and typos customers actually type.

Where does my data live?

In this browser's local storage for the demo/preview version of the app — see the Security audit below. A production deployment for a paying gym should move data server-side; see the Launch Guide's migration notes.

Can I cancel anytime?

Yes, from your Subscription page inside the dashboard — no contract, no cancellation fee. Full details on the pricing page.

What if my Wi-Fi drops mid-conversation with a customer?

The chat detects offline status and shows a clear "Offline" indicator instead of failing silently; replies resume automatically once connectivity returns.

Is there a free trial?

Every new gym gets a 14-day free trial on the Pro plan, no card required. Start it from Getting Started.

Security audit

This page is plain HTML, CSS, and JavaScript (loaded as ES modules). No build step, no minification, no external JS libraries. Nothing here is obfuscated — view source and you see exactly what runs.

WhatWhy it's here
Built-in FAQ matching (no network call)The chat answers directly from a built-in question list and each gym's own saved FAQ answers — entirely in the browser, no server round-trip needed to answer a customer.
localStorageStores gym info text and captured leads on this device only, via a single StorageAdapter module. Nothing is sent to any server GymBot QC controls.
No cookies, no analytics, no tracking pixelsNot needed for the demo.
No eval, Function(), or string-based setTimeout/setIntervalAll timers use function references, not code strings.
No iframes, hidden forms, or hidden downloadsNothing runs or downloads without a visible, deliberate button click.

Note: an optional Gemini API key field is still available in Setup in case AI-generated answers are re-enabled in a future update, but it currently plays no role in answering customers — nothing here sends chat messages to any external API.

ScenarioHandling

Complaint, injury, emergency, or billing disputeNever answered by guesswork — automatically routed to a "please contact our staff directly" message so a human handles it.
Empty or whitespace-only messageBlocked before sending — button stays disabled.
Very long messageInput is capped at 500 characters via maxlength and clamped again in code.
Rapid repeated clicksSend button disables the instant a message is sent and re-enables only after a reply or error.
Corrupted localStorageAll reads go through StorageAdapter's try/catch; a broken lead list or gym-info entry is reset instead of crashing the page.
CSV export with commas/quotes/emojiEvery field is quote-wrapped and internal quotes escaped before export.
Booking form left blankName and phone are required before "Confirm booking" is enabled; inline error text explains what's missing.
Customer goes offline mid-chatDetected via navigator.onLine before wasting a network call; header shows an "Offline" status and replies fall back automatically until connectivity returns.
Deployment checklist
  1. Swap the demo gym info for the real client's info in the Setup panel, then export that text somewhere safe (it resets if the browser storage is cleared).
  2. Fill in each gym's real FAQ answers in Business Settings (Gym Owner dashboard) before sharing their widget link — the built-in list ships with placeholder text.
  3. Host on Netlify or GitHub Pages (both are free, both serve plain HTML/ES modules fine over HTTPS).
  4. Test on an actual Android phone, not just desktop Chrome — check the keyboard doesn't cover the input.
  5. Send the link to the gym owner and watch them use it once, live, before pitching the paid plan.
